# Бот для сравнения цен корзины (MVP)

Telegram-бот: присылаете прошлую корзину (текстом или CSV), бот находит те же товары или
аналоги в Пятёрочке, Самокате, Яндекс Лавке, ВкусВилле и Чижике и считает, где выйдет дешевле:
всё в одном магазине или с разбивкой на два сервиса, с учётом доставки и минимальной суммы заказа.

> **ВкусВилл — реальные цены** через официальный (экспериментальный) MCP-сервер ВкусВилла
> `https://mcp.vkusvill.ru/mcp`, плюс готовая ссылка на корзину.
> ⚠️ **Остальные сервисы — ВЫМЫШЛЕННЫЕ цены** (`data/mock_catalog.json`): у них нет официального
> публичного API или MCP, см. раздел «Что не проверено».

## Структура

```
bot.py                 — Telegram-бот (точка входа)
config.py              — настройки из .env
pipeline.py            — полный цикл: разбор → сопоставление → расчёт → отчёт
models.py              — структуры данных (позиция, предложение, доставка, совпадение)
units.py               — фасовка, приведение к кг / л / шт, цена за единицу
services.py            — названия сервисов
rules.py               — сопоставление товаров по правилам (основной режим, API не нужен)
textnorm.py            — нормализация названий: слова, основы слов, жирность
matching.py            — выбор совпадений + проверка кодом, пометки «аналог» и [uncertain]
llm.py                 — необязательно: вызов Claude, если задан ANTHROPIC_API_KEY
comparison.py          — итог по сервисам, разбивка на два, экономия
report.py              — текст ответа и список для ручного заказа
parsers/               — разбор текста, CSV (и скриншота — только с ключом Anthropic)
providers/             — провайдеры цен: общий интерфейс, mock, MCP ВкусВилла (vkusvill_mcp.py),
                         заглушки остальных сервисов (TODO)
data/                  — mock-каталог и примеры корзин
tests/                 — автоматические проверки
```

## Запуск (для новичка)

1. **Установите Python 3.10+** с https://www.python.org/downloads/ (в Windows при установке отметьте
   галочку «Add Python to PATH»). Проверка в терминале: `python --version` (в macOS/Linux — `python3 --version`).
2. **Скачайте проект**: на странице репозитория на GitHub выберите ветку, нажмите «Code → Download ZIP»
   и распакуйте архив. Откройте терминал в папке проекта.
3. **Создайте виртуальное окружение и установите зависимости**:
   - Windows:
     ```
     python -m venv .venv
     .venv\Scripts\activate
     pip install -r requirements.txt
     ```
   - macOS / Linux:
     ```
     python3 -m venv .venv
     source .venv/bin/activate
     pip install -r requirements.txt
     ```
4. **Получите токен бота**: в Telegram напишите @BotFather → `/newbot` → придумайте имя → он пришлёт токен
   вида `123456:ABC...`.
5. **Ключ Anthropic не нужен.** Бот сопоставляет товары по правилам, бесплатно. Строку `ANTHROPIC_API_KEY`
   оставьте пустой. (Если когда-нибудь впишете ключ, бот начнёт выбирать совпадения через Claude и
   сможет читать скриншоты; вызовы платные.)
6. **Создайте файл `.env`**: скопируйте `.env.example` в `.env` и впишите токен бота:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   REGION=Москва
   ```
7. **Проверьте, что всё работает** (без Telegram и без интернета): `python -m pytest`
   — должно быть `30 passed`.
8. **Запустите бота**: `python bot.py`. Пока окно терминала открыто, бот работает. Остановить — Ctrl+C.
9. **Отправьте боту тестовую корзину**: откройте бота в Telegram, нажмите «Start» и вставьте текст из
   `data/sample_cart.txt` или отправьте файл `data/sample_cart.csv`.

### Запуск на GitHub (без своего компьютера)

1. На GitHub откройте репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
   Name: `TELEGRAM_BOT_TOKEN`, Secret: токен от @BotFather. Токен **никогда** не пишите в файлы проекта —
   репозиторий публичный.
2. Вкладка **Actions** → слева «Запуск бота» → **Run workflow** → укажите, сколько минут работать (до 350) → Run.
3. Пока запуск идёт (жёлтый кружок), бот отвечает в Telegram. По истечении времени он остановится;
   чтобы продолжить — запустите снова. Новый запуск сам останавливает предыдущий.
4. Тесты («Тесты» во вкладке Actions) запускаются автоматически при каждом изменении кода.

Ограничения: GitHub Actions — среда для сборки и тестов, а не хостинг. Один запуск живёт не дольше 6 часов,
и правила GitHub не разрешают использовать Actions как постоянный сервер. Для проверки это подходит;
чтобы бот работал круглосуточно, нужен сервер (VPS или хостинг для ботов).

### Озон Фреш: цены из ваших корзин

Официального API или MCP с ценами Озон Фреш нет, поэтому бот не запрашивает текущие цены Озона, а
**запоминает цены из ваших корзин**:

1. Пришлите боту корзину Озон Фреш: первой строкой `Озон Фреш`, дальше позиции как обычно
   (или CSV с сервисом «Озон Фреш»). Бот ответит «Запомнил цены Озон Фреш: N шт.».
2. В следующих сравнениях Озон Фреш появится как ещё один сервис с пометкой
   «цена из вашей корзины от ДД.ММ.ГГГГ». Цена старше 30 дней помечается [uncertain].
3. Бот знает только те товары, которые вы уже покупали; новая покупка обновляет цену.
4. Условия доставки Озон Фреш боту неизвестны и по умолчанию не учитываются. Посмотрите их в приложении
   Ozon для своего адреса и задайте (в рублях, 0 — не учитывать):
   - `OZON_FRESH_DELIVERY_FEE` — стоимость доставки;
   - `OZON_FRESH_FREE_FROM` — сумма заказа, с которой доставка бесплатная;
   - `OZON_FRESH_MIN_ORDER` — минимальная сумма заказа.

   На своём компьютере — в файле `.env`. На GitHub — в репозитории **Settings → Secrets and variables →
   Actions → вкладка Variables → New repository variable** с теми же именами, затем перезапустите бота.

Цены хранятся отдельно для каждого пользователя Telegram в `data/user_prices.json` (в git не попадает).
При запуске на GitHub файл между запусками лежит в кэше GitHub Actions в зашифрованном виде
(ключ — секрет `TELEGRAM_BOT_TOKEN`). Кэш удаляется, если бота не запускать 7 дней; перезапускайте бота
после окончания предыдущего запуска — иначе цены, сохранённые в последние минуты старого запуска, могут потеряться.

### Формат текстовой корзины

```
Пятёрочка
Молоко Простоквашино 2,5% 930 мл — 2 шт — 96.99 ₽
Бананы 1 кг x2 139 руб (Самокат)
Хлеб Бородинский 400 г; 1; 55; Чижик
```
Строка с одним названием сервиса задаёт сервис для следующих строк. Фасовку пишите в названии (930 мл, 1 кг, 10 шт),
цену — за одну упаковку.

### Формат CSV

Колонки: `название;бренд;фасовка;количество;цена;сервис` (можно через запятую, английские названия тоже подходят).

## Как это работает

1. **Разбор**: текст и CSV разбираются правилами (скриншоты — только с ключом Anthropic).
2. **Кандидаты**: провайдер каждого сервиса ищет до 10 похожих товаров.
3. **Сопоставление по правилам** (`rules.py`):
   - тип товара должен совпасть: «Молоко» ищется среди молока, «Сыр» — среди сыров;
   - взаимоисключающие виды отсекаются: молотый кофе ≠ растворимый ≠ в зёрнах, газированная вода ≠ негазированная;
   - выбирается кандидат с наибольшим совпадением слов; бренд, фасовка и жирность добавляют балл,
     лишние слова («с малиной», «с кремом») — снимают;
   - отличия записываются причиной: «другой бренд», «другая фасовка (900 мл вместо 930 мл)»,
     «другая жирность», «отличается вид: «варёная»».
4. **Проверка**: разные единицы (кг против л), неизвестная фасовка, слабое совпадение или цена за кг/л,
   отличающаяся больше чем в 2,5 раза, дают пометку **[uncertain]** — такие строки проверьте глазами.
5. **Количество**: считается по объёму — 2 × 930 мл превращаются в 2 × 950 мл или в 4 × 500 мл.
6. **Итоги**: для каждого сервиса — товары + доставка (бесплатно от порога), проверка минимальной суммы;
   лучшая разбивка на два сервиса перебором вариантов; экономия относительно того, как вы покупали.
7. **Заказ**: только вручную — бот выдаёт список с галочками. Для ВкусВилла — ещё и ссылку на корзину
   с уже добавленными товарами (её создаёт MCP-сервер ВкусВилла); заказ вы оформляете сами.

### MCP ВкусВилла: что важно знать

- Сервер помечен ВкусВиллом как экспериментальный: формат ответа или адрес могут измениться. Если он
  недоступен, бот продолжит работу, а в отчёте напишет «ВкусВилл: источник недоступен».
- Сервер закрыт защитой QRATOR. Клиент httpx, который использует бот, она пропускает (проверено),
  а стандартный `urllib` из Python — нет. Бот ничего не маскирует; если защита начнёт блокировать бота,
  нужно писать в поддержку ВкусВилла, а не обходить её.
- Чтобы вернуть ВкусВилл на mock-данные, поставьте в `.env` строку `VKUSVILL_SOURCE=mock`.
- Если бот запущен в облачной среде с ограниченной сетью, разрешите домен `mcp.vkusvill.ru`.

### Риски при подключении реальных цен

- **Юридические**: у Пятёрочки, Самоката, Яндекс Лавки и Чижика нет официального публичного API
  для цен. Автоматический сбор данных с сайтов и из приложений может нарушать пользовательские соглашения;
  использование закрытых (неофициальных) API приложений — тем более. Перед подключением нужна проверка
  соглашений и, по-хорошему, консультация юриста. Легальные пути: партнёрские программы, собственные
  ручные записи цен, официальные выгрузки, если сервис их предоставляет.
- **Технические**: цены и наличие зависят от адреса, времени и промоакций, персональных скидок и карт
  лояльности; сайты защищены от ботов и часто меняются; условия доставки меняются динамически (погода,
  загрузка). Обход SMS-авторизации и антибот-защиты в проекте не делается и делаться не должен.
- **Качество сопоставления**: правила не «понимают» товар так, как человек: вкус, сорт или назначение
  могут не учитываться, поэтому пометки «аналог» и [uncertain] нужно просматривать глазами. Списки видов
  товаров (`HARD_GROUPS`, `SOFT_FLAGS` в `rules.py`) можно пополнять.
